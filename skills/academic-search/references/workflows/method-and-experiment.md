# 从论文方法到一个可检验的问题

**解释一个模块时**，从一个具体样本沿图中箭头走一遍。说明每一步接收什么、产出什么、谁使用这个输出。对语义表示尤其要问清它属于字段、物品还是用户，在哪个阶段生成，训练和推理时是否都可用。只展开与当前疑问有关的步骤。

如果问题涉及实现细节，先定位论文的图、公式或实验段落。能取得对应代码时，再沿实际调用路径查生成、保存、加载及损失计算的位置，并给出文件或函数。论文描述、该版本代码的行为、已运行的结果分别注明依据。作者未报告随机种子数或某项消融时，保留为未知；一次公开运行配置只能证明该配置的设置。

**比较论文与自己的方法时**，对齐表示的粒度、输入中可用的信息和训练目标。例如，一个字段共用一个语义向量，与每个物品各有一个向量，检验的是两个不同问题。即使都加了辅助损失，也要说明损失两端分别是什么、更新哪些参数。

**讨论最小实验时**，先说清已有基线看得见什么，以及新方法预期改变哪一步。如果提出问答或属性增强，区分外部新增信息、从原输入推导出的表示，以及额外监督；三者都可能有价值，所需对照不同。围绕当前假设选最省的一组比较，保持数据划分和评估口径可比，并说明哪种结果会削弱这个解释。例如，想判断物品级语义是否有用，可以保持模型和向量不变，只打乱向量与物品的对应，观察指标如何变化。这个对照检验对应关系的作用，单凭它仍难判定收益来自哪个具体语义属性。
